# Reproduction Guide

This guide covers the programs and saved measurements supporting
*A New Framework for Efficient Multivariate Functional Bootstrapping*.
Begin with `TABLE_INDEX.csv`: it links each reported result to the precise
input, raw observations, summary and source snapshot. The index selects 81
main-table means and three supplementary means; older records are not substitutes.

## Prepare a separate workspace

Run these commands from the repository root in Linux or WSL:

```bash
python3 scripts/verify_artifact.py
python3 scripts/prepare_workspace.py --list
python3 scripts/prepare_workspace.py --output ../reproduction
source ../reproduction/environment.sh
```

Python 3.11 or newer is required for the preparation and verification tools.
The output directory must not exist. Preparation copies source, inputs and
parameters; it does not compile programs or run experiments. It omits saved
result directories so fixed output names cannot overwrite published records.
`environment.sh` sets the named directories used below. To prepare another run,
choose another new output directory. `--dry-run --output NEW_DIRECTORY` checks
the copy plan without writing; `--include-records` is for historical inspection,
not a fresh experiment workspace.

## Dependencies

Use Python 3.11 or newer for the release checks. Use Rust/Cargo with the pinned toolchain declarations; BBR explicitly uses
Rust 1.96.0. The retained Meta modules declare Go 1.24; the initial recorded
runs used Go 1.24.0, with each run's actual version retained in its environment
record. Python 3 is sufficient for the new release tools.
The shell scripts also use `taskset`, `sha256sum`, and `/usr/bin/time`.

The frozen Rust scripts build offline. Fetch the locked dependencies once with
network access before an offline reproduction:

```bash
rustup toolchain install 1.96.0
for crate in \
  "$OURS_SMALL/ours" "$OURS_LARGE/ours" \
  "$BBR/source/HLUT-rs" \
  "$BBR_DIVISION/source/HLUT-rs" \
  "$DIVISION_T8/source/section3" \
  "$DIVISION_T8/source/refined-tfhe-lhe" \
  "$REFINED_SMALL/source/refined-tfhe-lhe" \
  "$REFINED_STATISTICS/source/refined-tfhe-lhe" \
  "$REFINED_DIVISION/source/refined-tfhe-lhe" \
  "$QUOTIENT_PROTOCOL/source/section3" \
  "$QUOTIENT_PROTOCOL/source/refined-tfhe-lhe"; do
  (cd "$crate" && cargo +1.96.0 fetch --locked)
done
```

Meta's frozen initial runner uses a local GOPATH; prepare that cache for all
three groups, then the scripts' `GOPROXY=off` setting can work:

```bash
export GOPATH="$META_INITIAL/toolchain/gopath"
mkdir -p "$GOPATH"
for crate in "$META_INITIAL/source/META-FBS" \
             "$META_STATISTICS/source/META-FBS" "$META_SMALL/source/META-FBS" \
             "$DIVISION_T8/source/META-FBS"; do
  (cd "$crate" && GOPROXY=https://proxy.golang.org,direct go mod download)
done
```

No dependency cache, compiler installation, or binary is distributed. Internet
access is required for the initial downloads unless those dependencies are
already cached. Installing dependencies does not reproduce an experiment; the selected measurement commands below must be run separately.

## Final function tables

Run one measurement job at a time. The commands use the recorded eight-thread
budget and CPU affinity; CPU numbering may require adjustment on another machine.
`RUN_ID` is generated by `environment.sh`; choose a new value for another attempt.

```bash
# Small-domain and counting table
(cd "$OURS_SMALL" && bash scripts/build_ours.sh "build_$RUN_ID" && \
 taskset -c 0-7 bash scripts/run.sh "protocol_$RUN_ID")

# Six-input table (runner retains its full frozen ten-task group)
(cd "$OURS_LARGE" && bash scripts/build_ours.sh "build_$RUN_ID" && \
 taskset -c 0-7 bash scripts/run_ours.sh "protocol_$RUN_ID")

# BBR explicit decompositions with the author evaluator
(cd "$BBR" && bash scripts/build.sh "$BBR/results/build_$RUN_ID" && \
 taskset -c 0-7 bash scripts/run_functions.sh "$BBR/results/functions_$RUN_ID")
(cd "$BBR" && bash scripts/build_small.sh "$BBR/results/build_small_$RUN_ID" && \
 taskset -c 0-7 bash scripts/run_small_functions.sh "$BBR/results/small_$RUN_ID")

# Refined-LHE (these runners use fixed names: prepare a new workspace to repeat)
(cd "$REFINED_STATISTICS" && bash scripts/build.sh "build_$RUN_ID" && \
 taskset -c 0-7 bash scripts/run_all.sh)
(cd "$REFINED_SMALL" && bash scripts/build.sh "build_$RUN_ID" && \
 taskset -c 0-7 bash scripts/run_all.sh "$SMALL_INPUTS/inputs")

# Meta statistics/Hamming/t32 quotient, then small-domain statistics
(cd "$META_STATISTICS" && bash scripts/build.sh "build_$RUN_ID" && \
 taskset -c 0-7 bash scripts/run.sh "protocol_$RUN_ID")
(cd "$META_SMALL" && bash scripts/build.sh "build_$RUN_ID" && \
 taskset -c 0-7 bash scripts/run.sh "protocol_$RUN_ID")
```

The table index, not the number of cases emitted by an entire runner, specifies
which measurements enter each paper cell. Earlier grouping/classical-PBS values
are retained and must not replace the final small-capacity/multibit results.

## Quotients

The main comparison uses t=8,16,32. Existing t=64 observations remain
supplementary. The fresh workspace includes one recorded compatibility patch
to the t8 runner: old build caches become optional, and an installed Go
toolchain can replace the unshipped local toolchain. The original published
runner and all algorithm source remain untouched. See `PREPARATION_PATCH.diff`.

```bash
# t8: Ours, Native, Refined and Meta; fixed attempt name requires a new workspace
(cd "$DIVISION_T8" && bash scripts/run_t8.sh)

# BBR t8/t32: reuse the verified offline decompositions (no new search required)
(cd "$BBR_DIVISION" && bash scripts/run_fhe.sh 8 \
 "$ARTIFACT/experiments/bbr_division/results/search_t8_attempt1" \
 "$DIVISION_T8/inputs/division_t8.csv" "$BBR_DIVISION/results/fhe_t8_$RUN_ID")
(cd "$BBR_DIVISION" && bash scripts/run_fhe.sh 32 \
 "$ARTIFACT/experiments/bbr_division/results/search_t32_attempt1" \
 "$QUOTIENT_PROTOCOL/inputs/division_t32.csv" "$BBR_DIVISION/results/fhe_t32_$RUN_ID")

(cd "$QUOTIENT_PROTOCOL" && bash scripts/build_final.sh "build_$RUN_ID" && \
 taskset -c 0-7 bash scripts/run_division_suite.sh "$RUN_ID" && \
 taskset -c 0-7 bash scripts/run_one.sh refined_div 16 none "${RUN_ID}_refined_div16")

(cd "$REFINED_DIVISION" && bash scripts/build.sh && \
 taskset -c 0-7 bash scripts/run_one.sh 32 && \
 taskset -c 0-7 bash scripts/run_one.sh 64)

(cd "$META_INITIAL" && bash scripts/build_meta.sh "build_$RUN_ID" && \
 taskset -c 0-7 bash scripts/run_meta.sh div 16 none "${RUN_ID}_div16")

# Successful BBR t16: same searched decomposition, revised PBS decomposition
(cd "$BBR" && bash scripts/run_division_fhe_pbs15x2.sh \
 "$ARTIFACT/experiments/bbr/results/division_search_fixed_attempt1" \
 "$BBR/results/division_pbs15x2_$RUN_ID")
```

The BBR t8, t16 and t32 commands include 21, 47 and 128 PBS calls respectively.
Their revised parameters have no new
failure calibration. Read the retained diagnosis at
`experiments/bbr/evidence/DIVISION_ROOT_CAUSE_AND_REPAIR.md` before interpreting
the original failures. Refined's fixed output directories also require a new
workspace for repeated quotient runs. Meta t32 already runs in the group above.

## Optional offline BBR search

This is unnecessary for reproducing the retained successful decomposition. To
repeat the bounded search, install the retained author's decomposer and set
`BBR_PYTHON` explicitly; a development-machine virtual environment is not shipped:

```bash
python3 -m venv "$BBR/.venv"
source "$BBR/.venv/bin/activate"
python -m pip install numpy==2.2.6 pandas==2.3.0 galois==0.4.6 click==8.3.2 maturin==1.9.4
cargo +1.96.0 fetch --locked \
  --manifest-path "$BBR/source/decomposer/src/gauss_elimination_rs/Cargo.toml"
(cd "$BBR/source/decomposer" && maturin develop --release)
export BBR_PYTHON="$BBR/.venv/bin/python"
(cd "$BBR" && bash scripts/run_division_search_fixed.sh "$BBR/results/search_$RUN_ID")
```

The original exact dependency versions and loaded-source hashes are in the
retained search/environment logs and `archive/historical_results/records/bbr_initial/evidence/`.

## Statistics and provenance

All 84 measured table means can be rebuilt directly from the retained logs:

```bash
python3 "$ARTIFACT/scripts/rebuild_statistics.py" \
 --output "$REPRODUCTION/statistics_check" --run-frozen-parsers
python3 "$ARTIFACT/scripts/check_workspace.py" "$REPRODUCTION" \
 --report "$REPRODUCTION/workspace_check.json"
```

The first command also runs the original BBR and four-method t8 statistics
scripts in isolated record copies. It never invokes a compiler, search, key
generation or encrypted computation. This command checks the recorded aggregates. It does not rerun encrypted evaluation or recalibrate any failure probability.

Use thirty timed observations and preserve the five warm-ups. Source summaries
explicitly distinguish population and sample standard deviations. Do not
rename one convention as the other. Some historical summary scripts bind
specific attempt names: adapt only their paths in the new working copy, keep
that diff, and write a new summary. BBR's function summary scripts accept the
run directory and `--output-dir` directly.

The paths in original logs identify the environment in which those runs were
made. The preparation script restores the required paths in a separate
execution workspace; users do not need the original developer directory.
`docs/provenance/file_map.csv` records the correspondence. Earlier records are
under `archive/historical_results/` and are not the source of final table cells.

## Interpreting a reproduction

- Check decrypted outputs against the supplied plaintext answers before comparing time.
- Keep all five warm-ups and all thirty timed observations, including slower observations.
- Preserve failed attempts rather than replacing them with successful runs of another configuration.
- Retain each run's environment, full parameters, command, input snapshot and source hashes.
- Select main or supplementary rows using `TABLE_INDEX.csv`; a runner can emit more cases than one paper table uses.
- Compare the same function and domain. Small-domain timing is not a replacement for the six-input instance.
- Treat timing differences as configuration-specific. Encodings, security parameters and whole-computation failure probabilities are not unified across all methods.

`Supplementary_Notes.pdf` gives the parameter tables, timing boundary and
reliability limitations. `Function_Catalogue_and_Verification_Records.pdf`
defines the functions and distinguishes mathematical constructions, finite
checks and ciphertext measurements. No missing result is filled by an estimate.
